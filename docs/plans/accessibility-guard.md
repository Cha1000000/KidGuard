# План: контроль не должен молча отключаться

## Что выяснено опытами (эмулятор, Android 15)

| Действие | accessibility после |
|---|---|
| `adb install -r` (replace-установка, как из магазина) | **сохраняется** |
| `am force-stop` | **сбрасывается всегда** |

То есть слетает не «при обновлении», а при **принудительной остановке** приложения: Android при
force-stop сам вычищает сервисы пакета из `ENABLED_ACCESSIBILITY_SERVICES`. Отсюда жалоба Володи:
Android Studio и `gradlew installDebug` делают `am force-stop` перед установкой. Обновление из
RuStore этого не делает — у обычных пользователей этот сценарий не воспроизводится.

Что остаётся общим для всех: приложение остановили руками («Остановить» в настройках) или это
сделал вендорский оптимизатор (у Tecno — PhoneMaster), либо ребёнок выключил сервис в настройках
специально, чтобы снять лимиты. Последнее — дыра в защите: контроль отключается одним тумблером и
никто об этом не узнаёт до следующего heartbeat.

Включить accessibility программно обычному приложению Android не даёт — это защита платформы,
её нельзя обойти (Family Link решает это provisioning'ом при первичной настройке телефона).
Поэтому фикс состоит из двух слоёв.

## Слой 1 — универсальный (работает у всех, включая RuStore)

Новый **`AccessibilityGuardController`** в детском foreground-сервисе, рядом с остальными
контроллерами (`BlockingController`, `FullScreenLockController`, ...). Тик 15 секунд, как у
соседей — отдельный `ContentObserver` не нужен: отсрочка всё равно измеряется минутами.

Состояния:

1. **Всё в порядке** — ничего не делает.
2. **Разрешение пропало** — контроллер запоминает момент, немедленно дёргает
   `HealthReportTrigger.requestNow()` (родитель видит «контроль отключён» без ожидания 15 минут) и
   показывает ребёнку уведомление «Контроль отключён — верните разрешение».
3. **Отсрочка вышла** (`GRACE_MINUTES = 5`, ещё не восстановлено) — полноэкранный замок.
4. **Восстановлено** — замок и уведомление снимаются, снова heartbeat.

Логика решения выносится в `:core` чистой функцией и покрывается тестом (как `shouldBlock` и
`usageTickTargets`):

```kotlin
enum class ControlIntegrityAction { NOTHING, RESTORE, WARN, LOCK }

fun controlIntegrityAction(
    accessibilityEnabled: Boolean,
    canSelfRestore: Boolean,
    secondsSinceLost: Long?,
    graceSeconds: Long
): ControlIntegrityAction
```

### Замок — новый оверлей, не переиспользование существующих

`FullScreenLockOverlayManager` (ночной замок) и `PinOverlayManager` рисуются в
`TYPE_ACCESSIBILITY_OVERLAY` через WindowManager **самого accessibility-сервиса** — а он в этот
момент как раз выключен. Поэтому нужен `ControlLockOverlayManager` на `TYPE_APPLICATION_OVERLAY`
(WindowManager из Context, как в `OverlayManager`) — он от accessibility не зависит, работает на
одном `SYSTEM_ALERT_WINDOW`.

Отличия от мягкого блок-оверлея: не смахивается и не гаснет по таймеру. Содержимое:

- объяснение «Родительский контроль отключён»;
- кнопка **«Включить»** → `Settings.ACTION_ACCESSIBILITY_SETTINGS`. При нажатии замок прячется на
  `SETTINGS_GRACE_MINUTES = 2` — иначе он перекроет сами настройки и включить будет нечем;
  если разрешение так и не вернули, замок приходит обратно;
- ввод **PIN родителя** — снять замок, не восстанавливая разрешение (родитель может чинить телефон
  сам). Клавиатура PIN сейчас приватная внутри `PinOverlayManager`; её и проверку кода выносим в
  общий `PinKeypad`, чтобы не копировать вторую реализацию.

### Чтобы замок не мешал первичной настройке

Замок включается только если контроль **уже был настроен** — флаг «accessibility выдавалось хотя бы
раз» в DataStore, ставится при первом обнаружении включённого разрешения. Иначе замок выскочил бы
посреди мастера разрешений, где accessibility ещё и не выдавали.

## Слой 2 — самовосстановление (для телефонов, до которых есть доступ с компа)

Если приложению выдано `WRITE_SECURE_SETTINGS`, оно чинит разрешение само — молча и за секунды:

```bash
adb shell pm grant ru.homelab.kidguard android.permission.WRITE_SECURE_SETTINGS
```

- манифест: `<uses-permission android:name="android.permission.WRITE_SECURE_SETTINGS"
  tools:ignore="ProtectedPermissions" />` — обычному приложению система его не выдаёт, объявление
  нужно только чтобы `pm grant` сработал;
- `PermissionsManager.canRestoreAccessibility()` — `checkSelfPermission`;
- `PermissionsManager.restoreAccessibility()` — дописывает наш компонент в
  `ENABLED_ACCESSIBILITY_SERVICES` (**не затирая чужие сервисы**) и ставит `ACCESSIBILITY_ENABLED = 1`.

Разрешение переживает обновления, слетает при полной переустановке — тогда выдать заново той же
командой. Нет разрешения — работает слой 1, поведение прежнее. То есть магазинную сборку это
никак не ломает.

**Побочная польза:** закрывается дыра обхода — ребёнок выключает сервис в настройках, а тот
включается обратно раньше, чем ребёнок успеет открыть игру.

## Что НЕ решается (и почему)

После `force-stop` приложение мертво: Android не даёт stopped-приложению стартовать ни по
будильнику, ни по broadcast, ни после перезагрузки. Ни один слой тут не поможет — телефон остаётся
без контроля, пока KidGuard не откроют вручную. Единственная защита — watchdog: родитель видит
пропажу heartbeat (уже работает).

Радикальное решение — Device Owner (`setUserControlDisabledPackages` физически запрещает
force-stop), но provisioning возможен только на устройстве без аккаунтов, то есть телефон ребёнка
надо сбрасывать. Отдельная большая задача, в этот план не входит.

## Состав правок

1. `:core` — `ControlIntegrityAction` + `controlIntegrityAction(...)` и тест на таблицу состояний.
2. `PermissionsManager` — `canRestoreAccessibility()`, `restoreAccessibility()`.
3. Манифест `:platform` — `WRITE_SECURE_SETTINGS`.
4. `ControlLockOverlayManager` — новый оверлей на `TYPE_APPLICATION_OVERLAY`.
5. `PinKeypad` — общая клавиатура и проверка PIN, вынесенная из `PinOverlayManager`.
6. `AccessibilityGuardController` — цикл, отсрочка, решения, уведомление.
7. `KidGuardForegroundService` — запуск нового контроллера отдельным job (как соседи).
8. Флаг «контроль был настроен» в существующем DataStore детских настроек.
9. Строки — в `strings.xml`, без хардкода.

## Проверка

1. `./gradlew :core:test :app:assembleDebug`.
2. На детском эмуляторе, **с** выданным `WRITE_SECURE_SETTINGS`: выключить сервис в настройках →
   в течение ~15 секунд он включается сам, в логе запись о восстановлении.
3. **Без** разрешения (`pm revoke`): выключить сервис → сразу уведомление ребёнку и «контроль
   отключён» у родителя; через отсрочку — полноэкранный замок; кнопка «Включить» уводит в
   настройки и замок на 2 минуты уступает; после включения замок уходит сам.
4. PIN родителя снимает замок.
5. Проверить, что замок не появляется во время первичной настройки (мастер разрешений).
