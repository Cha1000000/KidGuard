# План: swipe-to-refresh на вкладках «Дети» и «Статистика»

## Контекст

Обе вкладки уже умеют обновляться — `ChildrenViewModel.refresh()` и `StatisticsViewModel.refresh()`
существуют и вызываются через `LaunchedEffect(Unit)` при **входе на вкладку** (`ChildrenScreen.kt:62`,
`StatisticsScreen.kt:75`). VM переживает переключение вкладок, поэтому единственный способ обновить
данные сейчас — уйти на другую вкладку и вернуться. Неудобно, когда изменения происходят на детском
устройстве, а родитель уже стоит на нужной вкладке (например, ждёт, пока изменится статус «Привязан»,
или проверяет свежую статистику).

Задача — добавить жест swipe-to-refresh (потянуть вниз) на обеих вкладках, дёргающий тот же
`refresh()`. Только родительская часть — `ChildScreen.kt` (детский экран «Сегодня») и остальные
детские экраны не трогаем, пересборка `:platform`/детского модуля не нужна.

## Компонент

Material3 `PullToRefreshBox` (`androidx.compose.material3.pulltorefresh`, artifact `material3` резолвится
в 1.4.0 через `composeBom = 2026.06.01`) — тот же API, что уже используется в проекте с
`@OptIn(ExperimentalMaterial3Api::class)` (уже стоит на `ChildrenScreen`, добавится и на
`StatisticsScreen`). Дефолтный индикатор (`PullToRefreshDefaults.Indicator`, встроен в
`PullToRefreshBox`, кастомный передавать не нужно) красится в `MaterialTheme.colorScheme.primary` —
то же самое, во что красится обычный `CircularProgressIndicator()` без явного tint, который уже
используется на этих же экранах для начальной загрузки. То есть цвет автоматически консистентен и
для тёмной, и для светлой темы — она уже определена в `Theme.kt` (`DarkColorScheme`/`LightColorScheme`),
никаких новых цветов заводить не нужно.

## Отличие «первая загрузка» от «свайп-обновление»

Сейчас `loading: Boolean` в обоих `UiState` означает и «идёт самая первая загрузка» (тогда экран
показывает крупный центральный `CircularProgressIndicator()` вместо контента), и вообще «идёт любая
загрузка». Если гонять его же для `PullToRefreshBox.isRefreshing`, при свайпе весь контент вкладки
на мгновение подменится на большой центральный спиннер — это не то поведение, которое ожидается от
pull-to-refresh (контент должен оставаться на месте, крутится только маленький индикатор сверху).

Добавляю отдельный флаг `refreshing: Boolean = false` в оба `UiState`:
- **`ChildrenViewModel.refresh()`**: если это не самая первая загрузка (т.е. `loading` уже `false`) —
  выставляет `refreshing = true` вместо `loading = true`, список при этом остаётся на экране;
  по завершении сбрасывает оба в `false`.
- **`StatisticsViewModel.refresh()`**: та же идея. Сейчас метод и так не трогает `loading` повторно
  (только выставляет `loading = false` в конце) — значит при свайпе контент и так не пропадает;
  нужно только добавить `refreshing = true` в начале (если уже была первая загрузка) и `false` во
  всех четырёх точках выхода (`noChildren`, `child == null`, ошибка загрузки usage, успех).

`PullToRefreshBox(isRefreshing = uiState.refreshing, onRefresh = viewModel::refresh, ...)` — на
`loading` не завязываем: во время самой первой загрузки `refreshing` остаётся `false`, поэтому
верхний индикатор pull-to-refresh не дублирует уже показанный крупный центральный спиннер.

## Где именно оборачивать

- **`ChildrenScreen.kt`**: `PullToRefreshBox` оборачивает `LazyColumn` (список детей), не весь экран —
  `ScreenTitle` наверху остаётся неподвижным. Модификатор `Modifier.weight(1f)` вместо текущего
  `fillMaxSize()` на `LazyColumn` (сам `PullToRefreshBox` получает `weight(1f).fillMaxWidth()` как
  новый прямой потомок `Column`).
- **`StatisticsScreen.kt`**: `PullToRefreshBox` оборачивает весь `when { loading -> …; noChildren -> …;
  error -> …; else -> StatisticsContent(uiState) }` — так свайп работает независимо от того, в каком
  состоянии сейчас вкладка (не только когда данные уже показаны). Ветки `when`, использующие
  `Modifier.weight(1f)` (это `ColumnScope`-API), меняются на `Modifier.fillMaxSize()`, потому что
  внутри `PullToRefreshBox` они окажутся в `BoxScope`, а нужный размер уже задаёт сам `PullToRefreshBox`
  через `weight(1f)` на уровне внешнего `Column`.

## Что НЕ меняется

- Данные всё ещё приходят через уже существующие `refresh()` — новых запросов к серверу не добавляю.
- `ChildScreen.kt` (детский экран) и остальной детский UI/сервисы не трогаю.
- `LaunchedEffect(Unit) { viewModel.refresh() }` на входе во вкладку остаётся как есть — swipe добавляется
  вторым, ручным способом обновления, а не заменяет автоматический при входе.

## Проверка

На эмуляторе (родительская роль), обе темы (светлая/тёмная):
1. Вкладка «Дети»: свайп вниз показывает индикатор, список не пропадает, после ответа сервера
   обновляется (если состояние на детском устройстве поменялось — например, статус «Привязан»).
2. Вкладка «Статистика»: то же самое, включая состояния «нет детей» и «ошибка загрузки».
3. Цвет индикатора соответствует акцентному цвету текущей темы (сверить визуально с обычным
   `CircularProgressIndicator`, который уже есть на этих экранах).
4. Первая загрузка вкладки (переход с другой вкладки) по-прежнему показывает крупный центральный
   спиннер, а не маленький pull-индикатор.
5. Детский экран «Сегодня» не пересобирался и не менялся (`git diff` не должен задевать `feature/child`).
