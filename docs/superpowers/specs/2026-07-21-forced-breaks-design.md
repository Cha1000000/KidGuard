# Дизайн: принудительные перерывы («режим перерыва»)

- **Дата:** 2026-07-21
- **Статус:** согласовано (брейншторм), ждёт ревью спеки → план
- **Источник идеи:** Володя — кейс «родитель не задал лимитов, ребёнок залипает с утра до вечера».

## Контекст (зачем)

Все временные механизмы KidGuard отвечают на вопрос «сколько всего» и «когда нельзя»: дневной
лимит, пер-app лимиты, «Время учёбы» и «Время сна». Ни один не отвечает на вопрос **«сколько
подряд»**. Если родитель сознательно не ставит лимиты (доверяет, или ребёнок и так занят), телефон
можно не выпускать из рук весь день — вредно для зрения и осанки, а формально никакие правила не
нарушены.

Перерывы закрывают эту дыру: раз в N минут непрерывного залипания (или в назначенные часы) экран
блокируется на несколько минут с сообщением от родителя. Это профилактика, а не наказание —
поэтому механика отличается от лимитов: перерыв всегда конечен и заканчивается сам.

## Решения (из брейншторма с Володей)

1. **Жёсткость — несмахиваемый замок с обратным отсчётом.** Сам уходит по таймеру; экстренные
   контакты доступны; родительский PIN снимает его **до ближайшего гашения экрана**. Мягкий
   (смахиваемый) оверлей отвергнут: ребёнок смахнёт и продолжит залипать — фича не выполнит свою
   единственную задачу.
2. **Счётчик — непрерывное залипание.** Копится, пока экран включён; сбрасывается, если ребёнок
   сам отложил телефон достаточно надолго. Суммарное экранное время за день отвергнуто: перерыв
   прилетал бы даже тому, кто весь день брал телефон по пять минут.
3. **Где живёт** — кнопка «Перерывы» на экране «Дневной лимит», **под списком дней недели**,
   видна всегда.
4. **Когда действуют** — только в те дни, где лимит **не задан вообще** либо **больше 3 часов**.
   Порог считается по «голому» лимиту родителя, **бонусы не учитываются**.
5. **Перерывы не действуют в окне «Времени сна»** — там своя, более сильная блокировка.
6. **Режим «часы» — окна проходят мимо.** Каждый назначенный час это короткое окно блокировки
   (15:00–15:15): не брал телефон — не заметил; включил экран в 15:07 — видит замок с остатком.
7. **Предупреждение — одна плашка за 5 минут**, неблокирующим оверлеем (не уведомлением).
8. **Оформление оверлея** — переиспользует ночной замок, но фон без луны и звёзд: тот же
   индиго-градиент.
9. **Хранение** — в policy-документе, **сервер не меняется**.
10. **Заготовленных значений (дефолтов) нет** — интервал, часы и длительность родитель задаёт сам.

## Архитектура

### 1. Домен (`:core`)

```kotlin
// core/domain/model/BreakRules.kt
enum class BreakMode { INTERVAL, HOURS }

data class BreakRules(
    val enabled: Boolean,
    val mode: BreakMode,
    val intervalMinutes: Int,      // режим INTERVAL: залипания до перерыва
    val hours: Set<Int>,           // режим HOURS: минуты от полуночи (15:00 = 900)
    val durationMinutes: Int,      // длительность самого перерыва
    val message: String            // текст родителя на замке
)

sealed interface BreakState {
    data object Idle : BreakState
    data class Warning(val minutesLeft: Int) : BreakState
    data class Active(val secondsLeft: Int) : BreakState
}
```

Чистые функции (кандидаты в unit-тесты, файл тот же):

- `breaksApplyToday(dayLimitMinutes: Int?): Boolean` — `dayLimitMinutes == null ||
  dayLimitMinutes > LIMIT_THRESHOLD_MINUTES` (180). Бонус в расчёт не входит осознанно: порог
  описывает намерение родителя («я не ограничиваю жёстко»), а бонус — разовая поблажка.
- `nextBreakAt(hours: Set<Int>, nowMinuteOfDay: Int): Int?` — ближайшее окно режима HOURS.
- `hoursWindowAt(hours, duration, nowMinuteOfDay): TimeWindow?` — активное окно перерыва.
  Переиспользует `TimeWindow` из `Schedule.kt` (уже покрыт тестами, включая переход через полночь).

**Порог сброса счётчика залипания** = `durationMinutes`. Отдельной настройки нет: если ребёнок не
трогал телефон столько же, сколько длится перерыв, — перерыв фактически состоялся, гнать его
повторно незачем. Одна настройка вместо двух, и объяснимо родителю одной фразой.

### 2. Счётчик залипания (`:platform`)

`StickinessTracker` — тонкая обёртка над существующим источником экранного времени
(`ScreenTimeTracker` уже знает, когда экран включён и разблокирован; тот же механизм доказан на
реальном Tecno замером из Room):

- копит секунды, пока экран включён;
- сбрасывает счётчик, когда накопленная пауза (экран выключен) ≥ `durationMinutes`;
- **не тикает** внутри окна «Времени сна» и во время самого перерыва;
- обнуляется, когда перерыв доиграл свой таймер;
- живёт в памяти процесса. При перезагрузке сбрасывается — это корректно: ребут и есть пауза.

Мягкие блокировки (исчерпанный дневной лимит, «Время учёбы») счётчик **не останавливают**: их
оверлей смахивается, ребёнок продолжает пользоваться «Всегда доступными» и смотреть в экран.

### 3. Полноэкранные замки: один владелец окна (`:platform`)

Сейчас `SleepLockOverlayManager` — синглтон с единственным `overlayView`. Если завести второй
контроллер, дёргающий тот же менеджер, два контроллера начнут драться за окно (кто последний в
тике, тот и прав) — гонка, которая на эмуляторе может не проявиться, а на реальном устройстве
проявится. Поэтому:

- `SleepLockOverlayManager` → **`FullScreenLockOverlayManager`**, параметризованный:
  `LockAppearance.NIGHT` (небо, полумесяц, звёзды) и `LockAppearance.BREAK` (тот же индиго-градиент,
  без луны и звёзд), заголовок, вторая строка, наличие обратного отсчёта.
  Общее и неизменное: несмахиваемое окно `TYPE_ACCESSIBILITY_OVERLAY`, PIN-клавиатура, кнопки
  экстренных контактов, склонение имён через `RussianDative`.
- `SleepLockController` → **`FullScreenLockController`**: единственный владелец окна, решает по
  приоритету **сон > перерыв**. Внутри окна сна замок перерыва не показывается; если сон наступил
  посреди перерыва — перерыв уступает.
- Обратный отсчёт («Осталось 4:37») тикает в самом оверлее раз в секунду, чтобы не гонять
  контроллер.

Верный PIN снимает замок перерыва **до ближайшего гашения экрана**: родитель разблокировал, сделал
дело, погасил экран — замок вернулся (если перерыв ещё идёт). Ловим по `ACTION_SCREEN_OFF`, который
приходит и при нажатии кнопки питания, и при автогашении по таймауту; различить их нельзя, да и не
нужно — оба означают «телефон отложили».

Сам перерыв при этом продолжает идти по своему таймеру: замок — лишь видимая часть перерыва, а не
он сам. Снятый PIN-ом на третьей минуте десятиминутный перерыв закончится всё равно на десятой, и
после этого гашение экрана его уже не вернёт.

Ночной замок эту механику **не перенимает**: там PIN по-прежнему даёт 15 минут (решение Володи на
интервью по расписаниям — родитель может дать ребёнку договорить, не стоя над ним с горящим
экраном). Для перерыва 15-минутного окна не нужно: сам перерыв короче.

### 4. Плашка-предупреждение (`:platform`)

Новый `BreakWarningOverlay` — узкая полоса сверху, живёт ~4 секунды и исчезает с затуханием.

Почему не уведомление: heads-up в полноэкранной игре Android либо подавляет (Game Mode, immersive),
либо показывает поверх ровно в момент прицеливания, ещё и перехватывая тап. Плашка решает это
флагами `FLAG_NOT_TOUCHABLE | FLAG_NOT_FOCUSABLE | FLAG_NOT_TOUCH_MODAL`: тапы проходят насквозь в
игру, фокус не отбирается, приложение не сворачивается. Тип окна — `TYPE_ACCESSIBILITY_OVERLAY`,
как у замков: обычный `SYSTEM_ALERT_WINDOW` система прячет в immersive-играх (проверено на ночном
замке).

Показывается один раз за 5 минут до перерыва. В режиме INTERVAL это 5 минут **экранного** времени
(ребёнок гарантированно у телефона). В режиме HOURS — за 5 минут до начала окна; если экран
выключен, показывать некому — молча пропускаем.

### 5. Хранение и синхронизация (`:data`)

Room **8 → 9**, миграция `MIGRATION_8_9` (destructive запрещены):

```sql
CREATE TABLE break_rules (
    id INTEGER NOT NULL PRIMARY KEY,       -- всегда 0, одна строка
    enabled INTEGER NOT NULL DEFAULT 0,
    mode TEXT NOT NULL DEFAULT 'INTERVAL',
    intervalMinutes INTEGER NOT NULL DEFAULT 0,   -- 0 = не задано
    durationMinutes INTEGER NOT NULL DEFAULT 0,   -- 0 = не задано
    message TEXT NOT NULL DEFAULT ''
);
CREATE TABLE break_hour (minuteOfDay INTEGER NOT NULL PRIMARY KEY);
```

**Заготовленных значений нет** — интервал, часы и длительность задаёт родитель. Нули в схеме
означают «не задано»: пока длительность не задана и не задан ни интервал, ни хотя бы один час,
перерывы не срабатывают, а тумблер включения недоступен (как тумблер «Времени сна» без PIN).
Слайдеры на экране стартуют с пустого состояния, а не с подставленного числа.

`PolicyDocumentDto` получает `breakRules` **с дефолтами** (обратная совместимость со старыми
документами, как для `blockedSites`). Обязательно правится `canonicalJson` в `SyncRepositoryImpl` —
без этого push/pull начнут пинг-понговать. Счётчик залипания **не синхронизируется**: это локальное
состояние детского телефона, как `screen_time`.

Отдельно: `setBreak*`-сеттеры делают **точечные UPDATE**, а не пересоздают строку — на этих граблях
уже поскользнулись с `setBlockGoogleSearch`, который затирал тумблеры расписаний.

### 6. Родительский UI (`:app`)

**Кнопка «Перерывы»** на `DailyLimitScreen` под списком дней недели, видна всегда.

**Экран «Перерывы»** (`BreaksScreen` + `BreaksViewModel`, пакет `feature/parent/rules`):

- тумблер включения (временное отключение без потери настроек);
- выбор режима галочками (взаимоисключающе, как в «Запрете сайтов»): «Через интервал» /
  «В определённые часы»;
- слайдер интервала (20 мин – 3 ч), активен в режиме INTERVAL, стартует незаданным;
- список часов с добавлением и удалением, активен в режиме HOURS;
- слайдер длительности перерыва (5–30 мин), тоже стартует незаданным;
- поле текста для ребёнка: пустое, с примером в подсказке поля («Сделай перерыв! Дай глазам
  отдохнуть»). Если родитель ничего не ввёл, **эта же фраза показывается на замке** — иначе
  ребёнок увидит голый отсчёт без объяснения, зачем его прервали. Подстановка делается при
  отрисовке замка из `strings.xml`, а не записью в БД: так фраза остаётся редактируемой в одном
  месте и не «застывает» в политике;
- кнопка «Сбросить перерывы» (с подтверждением) — обнуляет и интервал, и часы;
- **подпись, в какие дни перерывы реально сработают** («Действуют: Пн, Ср, Сб — в остальные дни
  лимит 3 часа или меньше»). Без неё родитель поставит перерывы при лимите 2 часа и будет считать,
  что фича сломана.

Все тексты — в `strings.xml` (правило проекта). Макеты в `docs/ui-concepts/breaks/` согласуются
с Володей **до** кода.

## Границы задачи

- Сервер не меняется.
- Ветка — `sprint/pre-oleg-week` (накопительная до возврата телефона Олега).
- «Отложить перерыв на 2 минуты» — **не входит** (даёт рычаг тянуть время, усложняет логику).
- Показ ребёнку таймера «до перерыва» на экране «Сегодня» — **не входит** в v1.
- Вибрация при предупреждении — **не входит** (решение Володи: одна плашка, без вибро).

## Verification

1. **Unit (`:core`):** порог «лимит не задан / > 3 ч», ближайшее окно в режиме HOURS, активное
   окно, сброс счётчика по паузе, приоритет «сон бьёт перерыв».
2. **Сборка:** `./gradlew :app:assembleDebug`.
3. **Родительский эмулятор:** кнопка видна при любых лимитах; оба режима сохраняются; сброс
   очищает и интервал, и часы; подпись «действуют в дни …» пересчитывается при смене лимитов.
4. **Синхронизация:** правило доехало на детский; в логах `KidGuardSync` нет пинг-понга push↔pull.
5. **Детский эмулятор, режим INTERVAL:** выставить интервал 6 мин, длительность 5 мин → плашка за
   5 минут появляется поверх игры и **не перехватывает тапы**; далее замок с обратным отсчётом;
   сам уходит по таймеру.
6. **PIN на замке перерыва:** верный PIN убирает замок; гашение экрана до конца перерыва возвращает
   его с корректным остатком; после истечения таймера гашение замок уже не возвращает.
7. **Сброс счётчика:** погасить экран на время длительности перерыва → счётчик обнулился, замок не
   пришёл.
8. **Режим HOURS:** окно на «сейчас +2 мин»; при выключенном экране окно проходит мимо; включение
   экрана внутри окна показывает замок с остатком.
9. **Приоритет:** внутри окна «Времени сна» замок перерыва не появляется, счётчик не тикает.
10. **Дни без перерывов:** лимит 2 ч на сегодня → перерывы не срабатывают вообще.
11. **Ничего не задано:** тумблер недоступен, перерывы не срабатывают.
12. **Пустой текст:** родитель не заполнил поле → на замке показывается фраза-шаблон, а не пустота.
13. **Обратная совместимость:** старый policy-документ без `breakRules` применяется без падений;
    миграция 8→9 не теряет данные (проверить на живой БД обоих эмуляторов).
