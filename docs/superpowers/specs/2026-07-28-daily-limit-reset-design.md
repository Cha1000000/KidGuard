# Спека: кнопка «Сбросить сегодняшний лимит»

Дата: 2026-07-28. Ветка: `feature/add-day-limit-reload-button`.
Реализация — Sonnet 5 по плану, проверка — за ним.

## Зачем

Родитель берёт телефон ребёнка в начале дня (когда дневной лимит только начал тикать),
что-то проверяет/настраивает — и этим сам расходует выделенное ребёнку на сегодня время.
Закончив, родитель хочет **вернуть ребёнку израсходованное им время**, но не бонусом (бонус
_добавляет_ время сверх лимита), а именно **обнулив то, что потратил сам** — как будто день
только начался. Сейчас такой кнопки нет.

## Что делаем

На экране «Дневной лимит» — кнопка **«Сбросить сегодняшний лимит»**, которая обнуляет
израсходованное сегодня время: ребёнок снова получает полный дневной лимит на сегодня.

## Согласованные решения (брейншторм 2026-07-28)

1. **Расположение — вариант (в):** между блоком «Дополнительное время» и списком дней недели.
   Отдельная `OutlinedButton` (как «Перерывы»), с иконкой сброса. Обоснование: «Дополнительное
   время» и «Сброс» — оба про _сегодня_ (корректировка доступного на сегодня), логично рядом; а
   список дней ниже — настройка повторяющихся лимитов. Не внутри блока бонусов (там действие
   _добавляет_ время — противоположный смысл) и не вверху экрана (слишком заметно для нечастого
   действия).
2. **Охват — полный сброс за сегодня:** обнуляется И общий дневной счётчик (`screen_time`), И
   пер-app расход (`app_screen_time`) за сегодня. Чистый лист, как будто день только начался.
3. **Статистика тоже обнуляется:** израсходованное было потрачено родителем, а не ребёнком, —
   корректно убрать его из статистики. Экран «Статистика» у родителя покажет 0 за сегодня, отсчёт
   идёт с нуля.
4. **Бонусы не трогаем:** «Дополнительное время» — отдельные осознанные выдачи. После сброса
   остаток = дневной лимит + бонусы − 0.
5. **Кнопка активна только когда на сегодня задан лимит** (нет лимита — обнулять нечего; по образцу
   неактивной «Сбросить все лимиты», когда лимитов нет).
6. **Подтверждение:** диалог перед сбросом (защита от случайного нажатия), как у «Сбросить все
   лимиты».

## Механизм передачи «родитель → ребёнок» (по образцу бонусов; сервер не меняем)

Сервер policy-agnostic — политика едет непрозрачным JSON (LWW). Добавляем в policy-документ
**маркер сброса**: `dailyUsageReset = { date: "ГГГГ-ММ-ДД", issuedAt: <epoch-ms> }` (nullable,
дефолт null — обратная совместимость со старыми документами).

- **Родитель** (кнопка): `PolicyRepository.setDailyUsageReset(today, issuedAt)` — маркер попадает в
  локальную политику и в составе policy-документа уходит на сервер при push (как dailyLimits,
  bonuses и пр.). `issuedAt` — метка времени в момент нажатия.
- **Ребёнок** (в его sync-пути `pullAndApply`, ПОСЛЕ `applyDocument`): если
  `marker != null && marker.date == сегодня(ребёнка) && marker.issuedAt > lastAppliedResetAt`
  (последний применённый, хранится локально в DataStore) → обнулить сегодняшний `screen_time` и
  весь `app_screen_time` за сегодня, затем записать `lastAppliedResetAt = marker.issuedAt`.
  - **Идемпотентно:** тот же маркер повторно не срабатывает (issuedAt не новее последнего).
  - **Устаревание:** маркер за вчера (date≠сегодня) после полуночи игнорируется.
  - **Только на детском устройстве:** применение — в `pullAndApply` (детский цикл `childSyncLoop`),
    а не в общем пути. Родительский `switchActiveChild → applyDocument` маркер лишь кладёт в кэш и
    НЕ обнуляет ничего у родителя.

Почему `issuedAt`-таймстамп, а не «дата»: за один день родитель может нажать сброс несколько раз;
`issuedAt` даёт монотонный идемпотентный ключ, ребёнок применяет только новейший (по сути — один
сброс на нажатие). Таймстамп генерирует родитель в момент нажатия (его часы) — для идемпотентного
ключа этого достаточно, анти-отмотка тут не нужна.

## Изменения по слоям

**core** (`:core`)
- `UsageRepository`: новые методы `suspend fun resetScreenTime(date)` и
  `suspend fun resetAppScreenTime(date)` — обнулить общий и пер-app расход за день.
- Модель маркера: `data class DailyUsageReset(val date: LocalDate, val issuedAt: Long)` в
  `core/domain/model`.
- `PolicySnapshot` (+ поле `dailyUsageReset: DailyUsageReset?`) и `PolicyRepository`
  (потоки/сеттер `setDailyUsageReset(date, issuedAt)`, включение в снапшот).

**data** (`:data`)
- `UsageRepositoryImpl` + DAO: `@Query("DELETE FROM screen_time WHERE date = :date")` и
  `DELETE FROM app_screen_time WHERE date = :date`.
- `PolicyApi.PolicyDocumentDto`: `dailyUsageReset: DailyUsageResetDto? = null` (+DTO
  `{date: String, issuedAt: Long}`), дефолт null — обратная совместимость.
- Хранение маркера + `lastAppliedResetAt`: Room-миграция **9 → 10** (маркер — в `policy_flags`
  или отдельная строка; `lastAppliedResetAt` — в sync-DataStore ребёнка). Destructive-миграции
  запрещены.
- `SyncRepositoryImpl`: `applyDocument` (маппинг маркера в снапшот, как прочие поля),
  `currentLocalDocument`/`canonicalJson` (маркер в каноничный JSON — иначе push/pull пинг-понг),
  `pullAndApply` (проверка маркера → обнуление usage, запись `lastAppliedResetAt`).

**app** (`:app`)
- `DailyLimitScreen`: `OutlinedButton` «Сбросить сегодняшний лимит» между `BonusSection`-карточкой
  и карточкой дней; `AlertDialog`-подтверждение; активность по `limits.limitFor(today) != null`.
  Иконка сброса (новый `ic_reset.xml` или подходящая из Material).
- `DailyLimitViewModel`: `fun resetTodayUsage()` → `policyRepository.setDailyUsageReset(today, now)`.
- Все тексты — в `strings.xml` (хардкода нет — правило проекта).

## Крайние случаи

- **Полночь между выдачей и применением:** маркер устаревает (date≠сегодня) → не срабатывает.
- **Ребёнок офлайн** (у Олега интернет по расписанию): маркер доедет со следующим pull, применится
  один раз (идемпотентность по `issuedAt`).
- **Ребёнок был заблокирован** (лимит исчерпан): после обнуления `screen_time` поток `LimitState`
  пересчитывается (реактивно) → блокировка/оверлей снимаются автоматически.
- **Повторные нажатия:** каждый даёт новый `issuedAt`; ребёнок применит только новейший.
- **Обратная совместимость:** старый policy-документ без поля маркера читается как «сброса нет».

## Проверка (на эмуляторах + на реальном телефоне Олега)

1. `:core:test` — при наличии, юнит на модель/снапшот.
2. `:app:assembleDebug` — сборка.
3. Родитель (эмулятор): на дне с лимитом кнопка активна, без лимита — неактивна; диалог
   подтверждения; тап → маркер уходит на сервер (проверить `GET /policy`).
4. Ребёнок: «потратить» немного лимита (открыть приложение), затем сброс от родителя →
   `screen_time` и `app_screen_time` за сегодня обнулились (проверять БД **с `-wal`/`-shm`**),
   кольцо остатка на детском экране снова полное, статистика у родителя за сегодня = 0.
5. Идемпотентность: следующий pull того же маркера не обнуляет повторно (накопил время — не
   сбросилось само).
6. Разблокировка: исчерпать лимит (блокировка) → сброс → ребёнок разблокирован автоматически.
7. Обратная совместимость: применение старого документа без маркера не падает (миграция 9→10).

## Вне рамок

- Сброс лимита на прошлые/будущие дни (только сегодня).
- Отдельный сброс конкретного пер-app лимита (обнуляем весь пер-app расход за сегодня скопом).
- Изменения сервера.
